# UI/UX 고도화 기획안 (v3)

2026-10-17 · 웹 화면 전체 점검 결과와 개선 방향. 이전 단계는 `agent-office-ui-v2.md`(3D 사무실 중심 대시보드)다.

## 점검 방법

- 실제 서버(`serve.py`, 8000)와 모의 서버(`--mock`, 8001)를 띄워 브라우저로 둘러봤다.
- 데스크톱 1440×900(라이트), 휴대폰 375×812(다크).
- 사무실·업무 보드·에이전트·프로젝트·자료실·설정·타임라인·분석·검색(⌘K)·팀원 말 걸기·최종 보고서를 열었다.
- 모의 업무 1건을 처음부터 끝까지 돌렸다: 지시 → 계획 → 배정 → 실행 → 보고서.
- 동물원 공간과 실제 AI 실행 흐름(도구 허락 창, 이어 하기)은 이번에 직접 보지 않았다.

## 한 줄 진단

볼거리(3D 사무실)는 충분하다. 그런데 **업무를 맡기고, 지켜보고, 결과를 받아 다음으로 이어 가는 흐름**이 약하고, 메뉴와 상태 정보가 흩어져 있다.
v3 의 목표는 "구경하는 사무실"을 **"일이 끝까지 굴러가는 사무실"**로 바꾸는 것이다.

## 2. 개선 방향

### 원칙
1. **업무가 주인공, 사무실은 무대.** 업무가 없을 때는 사무실을 크게 보여 주고, 업무가 시작되면 업무 정보를 앞으로 꺼낸다.
2. **언제든 멈추고 고칠 수 있게.** 계획 확인, 중지, 다시 시도를 모든 단계에 둔다.
3. **결과는 다음 일의 시작.** 보고서에서 바로 복사·저장·후속 지시로 이어진다.
4. **상태는 숨기지 않는다.** 연결·실패·사용량을 평소 화면에서 바로 알 수 있게 한다.

### 2-1. 내비게이션 정리 (A1~A5, D4)

- 공간 선택 창은 **처음 한 번만** 띄운다. 그 뒤에는 설정 → '공간 테마'에서 바꾼다.
- 왼쪽 메뉴를 하나로 합친다: **사무실 · 업무 · 기록 · 에이전트 · 프로젝트 · 분석 · 설정**
  - '기록' = 타임라인 + 자료실을 합친 화면. 날짜별 목록과 검색, 성공·실패 필터를 둔다.
  - 숨어 있던 상단 탭(`#topnav`)은 지운다.
- 메뉴 이름과 화면 제목을 똑같이 맞춘다.
- 설정을 묶음으로 나눈다: **화면**(테마·조명·속도·움직임) / **사무실**(공간·위치·이름표) / **연결**(AI 연결 진단·접속 키·MCP) / **자동화**(결과 알림) / **정보**.

### 2-2. 업무 흐름 다시 짜기 (B1~B6) — 가장 중요

```
지시 → [계획 확인] → 실행(중지 가능) → 검수 → 보고서 → [후속 지시]
```

- **계획 확인 단계(선택):** 팀장 계획이 나오면 배정 표를 보여 주고 [이대로 실행] / [담당자 바꾸기] / [업무 빼기·추가]를 고를 수 있게 한다. 설정에서 '계획 확인 없이 바로 실행'도 고를 수 있다.
- **중지 버튼:** 상단 업무 카드에 [중지]를 둔다. 서버는 실행 중인 CLI 프로세스를 끝내고, 지금까지 결과를 체크포인트로 남긴다. 기존 '이어 하기'와 연결한다.
- **업무 카드:** 순서를 계획 순서로 고정하고, 상태는 색과 아이콘으로만 바꾼다. 카드를 누르면 오른쪽에 **업무 상세 패널**을 연다(담당자·지시 내용·실시간 출력·결과·재시도).
- **진행 표시:** 단계마다 글자를 맞춘다(계획 수립 중 → '계획 중', 배정 → '배정 중', 실행 → 'n/m 완료').
- **보고서 창:** 넓게 열고(최대 960px, 표는 가로 스크롤), [복사] [Markdown 저장] [폴더 열기] [이어서 지시] [다시 실행] 버튼을 둔다. [이어서 지시]는 보고서 내용을 첨부한 채 입력창을 채운다.
- **실패 화면:** 실패한 하위 업무와 원인(예: "claude 명령을 찾을 수 없음", "로그인 필요", "시간 초과")을 보여 주고 [이 업무만 다시] [다른 팀원에게]를 둔다.

### 2-3. 연결 상태가 보이는 팀 (C1~C3)

- 에이전트 카드와 오른쪽 팀원 얼굴에 **연결 표시**를 단다(초록 준비 / 노랑 로그인 필요 / 빨강 설치 안 됨).
- 설정 → 연결에 **'연결 진단'** 버튼: 서버가 CLI 별로 `--version` 확인과 짧은 1턴 시험 호출을 해서 설치·로그인·응답을 검사하고, 필요한 설치·로그인 명령을 복사 버튼과 함께 보여 준다.
  - 시험 호출은 구독 사용량을 조금 쓰므로 버튼을 누를 때만 한다.
- 업무 지시 전에 담당 팀원이 준비되지 않았으면 입력창 위에 경고를 띄우고 진단으로 안내한다.
- 상단 칩을 '서버 연결됨'에서 **'팀 3/3 준비'**처럼 바꾼다.

### 2-4. 화면 배치: 두 가지 모드 (D1~D3, D5)

- **둘러보기 모드(업무 없음):** 지금처럼 사무실을 크게 보여 준다. 빈 화면에는 예시 업무 칩 3개와 최근 업무 다시 하기를 둔다.
- **업무 모드(실행 중):** 사무실을 왼쪽 위 작은 창(또는 접기)으로 줄이고, 가운데에 **계획/업무 카드 보드**, 오른쪽에 **업무 상세 패널**을 둔다. 끝나면 보고서를 연 다음 둘러보기 모드로 돌아간다.
- 활동 로그에 팀원별 필터를 두고, 같은 팀원이 이어서 보낸 메시지는 한 묶음으로 접는다.
- 연출 속도는 설정과 사무실 도구 모음으로 옮긴다.

### 2-5. 휴대폰 (E1~E3)

- 누르는 영역을 모두 44px 이상으로 맞춘다(아이콘은 그대로 두고 여백을 늘린다).
- 방 전환은 가로로 넘기는 칩으로 바꾸고, 끝에 흐림 처리를 해서 더 있다는 것을 보여 준다.
- 업무 중에는 첫 화면에 업무 카드를 먼저 보여 주고, 3D 사무실은 접어 둔다.
- 아래쪽 탭 막대(사무실·업무·기록·설정)를 검토한다.

## 3. 단계별 진행 계획

| 단계 | 범위 | 포함 항목 | 규모 |
|---|---|---|---|
| **1단계 · 바로 고치기** | 작은 수정, 서버 변경 거의 없음 | A1 공간 창 한 번만, A2 분석·타임라인 메뉴 추가, A3 이름 통일, C1 카드에 연결 표시(기존 `ready` 활용), E1 터치 영역 | 반나절~1일 |
| **2단계 · 업무 흐름** | 서버 + 화면, `docs/events.md` 프로토콜 추가 | B1 중지(`POST /api/run/stop`), B3 카드 고정·상세 패널, B4 진행 표시, B5 보고서 버튼, B6 실패 원인·재시도 | 2~3일 |
| **3단계 · 계획 확인·진단** | 서버 + 화면 | B2 계획 확인 단계, C2 로그인 진단(`/api/team/diagnose`), C3 상단 '팀 준비' 칩 | 2일 |
| **4단계 · 배치 개편** | 화면 위주 | 2-4 두 모드 레이아웃, A4 '기록' 통합, D2 로그 필터, D4 설정 묶음, 휴대폰 첫 화면 | 3~4일 |

각 단계가 끝나면 다음을 확인한다: `pytest`, `python main.py --mock run "테스트"`, 데스크톱·휴대폰(라이트·다크) 브라우저 점검, 사무실·동물원 공간 둘 다.
